# 広聴AI CLIで自由記述を分析する

## 入力と実行計画を確かめる

1. 知りたいこと、対象ファイル、IDと本文の列を確かめる。対応が明らかなら、その対応を記録して進める。元CSVを保持し、必要ならUTF-8の作業用CSVに `comment-id` と `comment-body` を作る。IDは先頭ゼロも含めて文字列のまま保持する。ID列がなければ行との対応を残して一意なIDを振る。空の本文を除いた件数を記録し、ID重複など根拠を一意にたどれない問題を解消する。
2. `kouchou-analyze --help` で利用できるオプションを確認する。インストール、設定項目、プロバイダーの詳細は [CLIクイックスタート](../../docs/user-guide/cli-quickstart.md) を参照する。CLIが別の環境にあれば、その環境の `python -m analysis_core --help` も使える。設定には問いと入力名を入れ、指定されたモデルと送信先を使う。全件が対象なら `extraction.limit` を対象件数以上にする。省略時には上限がある版がある。
3. 新規分析なら独立した出力先を使い、次の形式で `--dry-run` を実行する。これはCSVの基本構造と実行計画の検証で、モデル接続と実行結果は本実行で確かめる。準備・検証だけの依頼ならここまでの結果を返す。分析する依頼なら同じ引数で `--dry-run` を外し、終了状態と生成されたファイルを確かめる。既存の出力を読む依頼では、その実行の結果JSONと元CSVを探す。

```sh
kouchou-analyze --config config.json --input-dir inputs --output-dir outputs --dry-run
```

## 結果を元コメントまでたどる

- `hierarchical_result.json` の `clusters` と `arguments` を読み、生成されたラベルや概要を手がかりにする。各所見は関連する `arg_id` と `comment_id` を調べ、元CSVの `comment-id` から本文を確かめる。同じ抽出意見に複数の元コメントが対応する場合は `relations.csv` も参照する。根拠として本文を引用する場合は元CSVから短く抜粋し、元CSVが参照できない場合は結果JSONで確認できた範囲を明示する。
- 入力コメント数、抽出された意見数、論点に関連する元コメントのユニーク数を区別する。見落としたくない声を探すときは、抽出に出てこなかったコメントや、小さなクラスタ、ラベルに表れない意見を確認する。抽出された意見の元コメントにも戻り、対象者や具体策など抽出で落ちた情報を確かめる。頻度が低くてもユーザーの問いに照らして重要な声を、その理由とIDとともに示す。
- 返す内容は分析範囲、根拠つきの主な論点、見落としたくない声、レポートと再実行用の設定へのリンク。ローカルで閲覧する場合は、生成されていれば `report.html` も渡す。抜粋やレポートの共有範囲は依頼に従う。

動作を試すときは、[架空の住民アンケート](assets/sample-resident-feedback.csv) を使える。`回答番号` と `自由記述` から作業用CSVを準備し、地域の改善要望を分析する。
