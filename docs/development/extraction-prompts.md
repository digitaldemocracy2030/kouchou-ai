# 入力に合わせて抽出プロンプトを調整する

「意見を抽出する」という指示が入力に合っていないと、短い語句から説明を補ったり、例示した文章を返したりすることがあります。まず元の入力と抽出結果を並べ、何を抽出したいかを決めます。入力を一律に削除するルールから始めないでください。

## 最初に決めること

| 入力の性質 | 決めること | 確認する失敗 |
| --- | --- | --- |
| 自由記述の要望・意見 | 1コメント内の複数意見をどこで分けるか | 原文にない理由や要望を足す |
| 単語・短い回答 | 意見として保持するか、キーワードとして扱うか | 短い語から長い主張を作る |
| 事実の記述・レシピ等 | 今回の調査対象に含めるか | 指示に合わせて無理に意見化する |
| 意見と無関係な入力 | 正常な空リストを許すか | few-shotの例をそのまま出力する |
| 否定・条件付きの文章 | 条件と否定を一緒に保持するか | 条件を落とし、賛否を反転する |

空リストは「その入力から対象の意見を抽出しなかった」という正常応答です。形式不正や通信失敗を空リスト扱いで続行しないことが重要です。

## 調整例（動作未検証）

以下は説明用に作成した仮想例です。モデルでの改善を実証したものではありません。利用する入力・モデルで小規模に比較してください。現在の応答形式 `extractedOpinionList` は維持します。

### 意見だけを抽出する場合

```text
入力に明示された意見・要望だけを抽出してください。
原文にない理由・背景・事実を追加しないでください。
否定と条件を保持してください。
対象となる意見がない場合は空のリストを返してください。
以下の例の内容を、実際の入力の意見として返さないでください。

入力: バスは増やしてほしいが、運賃が上がるなら現状維持でよい。
出力: {"extractedOpinionList":["運賃が上がらないならバスを増やしてほしい"]}
入力: 小麦粉と水を混ぜる。
出力: {"extractedOpinionList":[]}
```

### キーワードを分析する場合

```text
今回は文章の意見を補うのではなく、入力に明示されたキーワードを抽出します。
キーワードを長い主張へ展開しないでください。
出力のキーは extractedOpinionList とし、値は文字列の配列にしてください。

入力: 公園、街灯
出力: {"extractedOpinionList":["公園","街灯"]}
```

キーワードの集まりは、意見や支持の人数とは異なります。レポートの説明にも、何を抽出した分析なのか記載してください。

## 失敗例を集める

1. 入力に短文・長文・否定・無関係な文章を含む少量の比較セットを用意する。
2. 入力ID、原文、実際の抽出結果、期待する扱い、問題の種類を記録する。
3. モデル・provider・プロンプトの版・実行日・同じ入力セットを識別する名前も残す。
4. 通信・解析エラーと、正常に返ったが内容が不適切な結果を分ける。

```json
{"input_id":"synthetic-01","input":"公園、街灯","actual":null,"expected_policy":"キーワードを保持し、主張を補わない","problem_tag":"unsupported_expansion","verification":"動作未検証"}
```

`actual=null` は未実行を表します。予想した出力を実測として記録しません。原文付きの調査データは手元の非公開領域で管理し、共有するときは必要な範囲と共有権限を確認します。キー・API応答ログ・原文全件を公開Issueへ貼り付けないでください。

## 比較して採用する

標準プロンプトをbaselineとして保存し、同じ入力・モデルで指示またはfew-shotの一要素だけを変更します。各入力について、原文にない追加、欠落、否定・条件の変化、例文の混入、適切な空応答を確認してください。良くなった例だけでなく悪化した例も記録します。

seedを固定してもLLMの完全な再現性は前提にしません。差が小さい場合は同じ条件で再実行し、判断できなければ未確定とします。モデル変更とプロンプト変更を同時に行った結果は探索用として扱い、どちらが効いたかを断定しません。

本体とserverlessで比較する場合は、入力セット・プロンプト・選択モデルを揃え、処理対象や応答形式の違いも記録します。標準プロンプトの変更は、この比較を行った後の別変更として提案します。
