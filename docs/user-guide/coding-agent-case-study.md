# 事例: コーディングエージェントと広聴AIで、韓国日報のデータを分析する

[韓国日報（한국일보）との分析](https://dd2030.org/kouchou-ai/hankookilbo-2026/)は、ほとんどの作業を、人間が短い指示を出し、AIエージェント（コーディングエージェント）が進める形で行いました。このページでは、データを受け取ってから公開するまでの約4週間を、人間がエージェントに出した実際の指示とともに紹介します。「」で引用しているのは、人間がエージェントに出した指示です。

## 使ったもの

- エージェントは **Codex**（モデル `gpt-6-astra`、推論 high）と **Claude Code**（`claude-opus-5-5`）です。特に使い分ける意図はありませんでした。
- エージェントのモデルは、人間の指示を受けて作業する側のものです。広聴AIが意見の抽出や群名づけに使うモデル（今回は gpt-4.1）とは別です。
- エージェントは、広聴AIのコードと過去の作業記録を読める環境で動かしていました。
- 広聴AIが使う OpenAI API の利用は、エージェントとは別に許可と設定をしています。エージェントを契約すれば分析用の API も使える、というわけではありません。

## 1. まず、手元のデータで動かしてもらう

受け取ったのは、韓国の政治YouTube 6チャンネル（2026年1〜8月）のライブチャットを4通りに選んだ CSV（計7,497件）でした。人間がエージェントに出した最初の指示は「実際にデータを使って分析するのを試してみて」です。外に出してよい範囲もあわせて伝えました。

エージェントはまずデータを検査しました（件数、重複、添付の集計表との突き合わせ）。そのうえで、少ない件数で抽出のしかたを比べています。手元で動く小さなモデル（Qwen3 4B）は、6件中5件で主語の取り違えや原文に無い内容の追加があり、採用しませんでした。120件で gpt-4o-mini と gpt-4.1 を比べ、原文に忠実に抜き出すよう指示した gpt-4.1 に決めました（試行の費用は約0.33ドル）。

## 2. 試運転から全件へ、次に別の切り口へ

人間はエージェントに「さっさと全データでの分析をして、それから賛否比率をつけるかどうか考えよう」と指示しました。全件を OpenAI に送る前に、エージェントは送り先と件数（7,497件）を示して止まり、人間が「go」と答えてから実行しました。4種類のデータを並行して、20分ほどで処理しています。

このとき人間は、エージェントが試行の結果から gpt-4.1 を選んでいたことに気づかないまま「go」を出していました。終わってから「API費用はいくらかかってます？」と聞くと約15ドルで、「思ったよりかかってるな、どんなモデルを使った？」と驚くことになりました。gpt-4o-mini なら約1.2ドルという試算で、想定より1桁高くなっていました。モデルの選択と費用の見込みは、全件を流す前に確かめておくべきでした。

続いて人間がエージェントに提案しました。「6チャンネル均等より各チャンネルの方がいいのかも？extractionとembeddingは再利用できるから可視化だけ作るのはローコストだよね？」。エージェントは抽出した意見と埋め込みを使い回し、チャンネルごとの地図と群名だけを作り直しました（約1.4ドル）。

## 3. 説明に使う例を探し、配布物にする

人間がエージェントに「これらを眺めて何か面白い、記者さんに紹介すべきことはある？」と尋ねると、エージェントは群名と元の文を見比べて例を挙げました。保有税を上げるべきという意見と上げるなという意見が同じ群に入っている、などです。

取材の当日の朝には「実際に画面を示して解説する準備をしておきたい、言及している例がどこのことなのか教えて」と指示しました。エージェントは画面の辿り方を具体化し、その中で、群名が中身と合っていない群を見つけて「共通点の例として使わない」と注意書きを付けました。自分の前の説明の言い過ぎも1つ訂正しています。AIが挙げた例は、元の文に戻って確かめてから使います。

「先方が自分のマシンで見ることができるようにできる？メールで添付したい」と指示すると、エージェントはダブルクリックで開ける単独のHTML 10本と説明書を zip にまとめました。

## 4. 取材で出た要望を、広聴AIに実装する

取材では、記者から4つの要望が出ました。

1. ヘイト表現の割合を出せるか
2. 政策に関する意見の地図を作れるか
3. 全画面のまま、大きい群と細かい群を切り替えたい
4. 日本語・英語・韓国語を切り替えたい

取材の後、人間はエージェントに「デモを継続したいわけではない、インタビューは終わった、開発をしたい」と伝え、要望の実装に移りました。複数のエージェントに並行して実装させ、長時間の自走で仕上げさせています。

このときエージェントには、次の2つを指示しました。

- push や Issue・PR の作成は、エージェントが自分ではしない。変更は公開のリポジトリに出るので、出す前に人間が中身を確認する
- 取材のデータは使わず、広聴AIに含まれる公開のサンプルデータだけで動作を確かめる。取材のデータは非公開で、PR のスクリーンショットなどに映ってはいけないため

エージェントが仕上げた変更を人間が確認し、広聴AI本体への PR として出しました。いずれも取り込まれています。

- 要望1・2: 意見ごとに侮辱・ヘイト表現と政策提案のラベルを付ける任意のステップ（[#975](https://github.com/digitaldemocracy2030/kouchou-ai/pull/975)、[意見の分類ラベル](../development/opinion-classification.md)）
- 要望3: 全画面のまま粒度を切り替える（[#961](https://github.com/digitaldemocracy2030/kouchou-ai/pull/961)）
- 要望4: 日英韓の表示切替と翻訳のコマンド（[#1144](https://github.com/digitaldemocracy2030/kouchou-ai/pull/1144)、[v4.2.0](https://github.com/digitaldemocracy2030/kouchou-ai/releases/tag/v4.2.0) に収録）

## 5. 意見を分類する（ローカルモデル）

2,914件の意見それぞれに、侮辱・ヘイト表現にあたるか、政策・制度への提案か、を yes/no で付けました。ローカルの GPU で Ollama の qwen3.8:27b を動かし（temperature 0）、失敗は0件でした。侮辱・ヘイトは207件（7.1%）、政策提案は161件でした。

人間が「政策意見かつ侮辱なんてのがあるの？」と尋ね、エージェントは「AIが両方に分類した6件」と言い直しました。地図には「政策提案で、侮辱・ヘイトではない」155件を使っています（人間の指示は「155件版だけでいいよ」）。

## 6. 翻訳する（ローカルモデル）

記者が韓国語で読めるように、群名・説明・概要と、抽出した意見をすべて英語と韓国語に訳しました。OpenAI に送る形はエージェント側の自動の審査で止まったので、ローカルの GPU で Gemma 4 12B 系のモデルを動かして訳しています。外部の費用はかかっていません。

- 群名・説明・概要など901項目
- 抽出した意見7,598種類 × 英韓（最後の実行で約27分）。抜き取りで15か所を手で直しました

訳は人間による校正をしていません。

## 7. 記者に送る資料と、追加の図

人間がエージェントに「みられるものを作って、送る前にもちろん僕がみます」と指示すると、エージェントは1時間ほどかけて、分類結果の地図、訳、確認用のページ、zip までを作りました。見せ方は人間が決めています。たとえば「3ヶ国語の棒グラフは内容薄いからいらない」「目次のページがあるといいな」「マップのスクショを入れ込んで」です。エージェントが提案した、ヘイトの強い順に並べた照合表は「やらない」としました。

zip の中のスクリプトがメールで送れなかったので、ファイル共有の限定公開で渡しました。

記者からは追加の依頼が来ました。進歩寄りと保守寄りのチャンネルで色分けした図、ヘイト判定を除く前と後の比較、政策の意見のテーマ別の図です。エージェントは15分ほどで、日英韓の図48枚を作りました（LLMは使っていません）。さらに「点を除いてから座標を計算し直す方式も」という依頼に、乱数の種を5通り変えて配置を計算し直した図を作り、配置がどれくらい安定しているかも数えました。

## 8. 公開用のデータを作る

記事が出たあと、[デジタル民主主義2030のサイト](https://dd2030.org/kouchou-ai/hankookilbo-2026/)で分析結果を公開しました。データの提供元からは、元のデータをそのまま公開しないこと、個々のチャットを直接引用しないことを条件として伝えられていました。

- 画面は、[v4.2.0](https://github.com/digitaldemocracy2030/kouchou-ai/releases/tag/v4.2.0) の日英韓の切替に加え、その後 main に入った「元のコメント本文は、レポートごとに明示的にオンにしない限り公開しない」変更（[#1155](https://github.com/digitaldemocracy2030/kouchou-ai/pull/1155)）を含む版で作り直しました。画面だけを先にビルドし、公開用のデータを後から組み合わせる [shell 配布物](../development/static-shell-export.md)の方法を使っています
- 以前、記者の確認用に作ったデータには、元のチャット本文がそのまま入っていました（記者が原文と照らし合わせられるようにするため）。公開用にはこれを外し、原文へのリンクも外しました
- 公開するファイルすべてを、元のチャット7,136件と一字一句で照合しました。本文やリンクは残っていませんでした。ただ、短いチャットでは、抽出した意見の韓国語訳が元の文とほぼ同じになり、6件は完全に一致しました。人間がこれを確認したうえで、載せると判断しています

## うまくいかなかったこと

- **AIの説明の取り違え**: 試運転の結果を主な成果物のように案内した、既にある機能（単独のHTMLの書き出し）を見落とした、などを人間が指摘して直しました
- **モデルと費用の確認漏れ**: 2 で書いたとおり、エージェントが選んだモデルに気づかないまま全件を流し、想定より1桁高い費用になりました

外部へのデータの送信、PR の作成とマージは、エージェントの側の自動の審査で止まることがありました。止まったときは回避せず、人間が判断するか、人間が実行しています。

## 費用と時間

| 段階 | 費用・時間 |
|---|---|
| 抽出方法の試行（120件） | 約0.33ドル |
| 全件の分析（7,497件、4種類） | 約13.2ドル、並行で約20分 |
| チャンネル別の地図 | 約1.4ドル |
| 分類（2,914件） | 外部費用0、最後の実行で約9.5分 |
| 翻訳（7,598種類 × 2言語） | 外部費用0、最後の実行で約27分 |

費用は API の応答に含まれる使用量から計算した概算で、請求額ではありません。
